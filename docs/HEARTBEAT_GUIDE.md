# Heartbeat 心跳巡查指南

Heartbeat 是 LobsterAI 的主动巡查机制。它定期唤醒 AI Agent，让 Agent 主动检查是否有需要你关注的事项——不需要你手动提问。

## 它和定时任务有什么区别？

| | 定时任务 (Scheduled Task) | 心跳巡查 (Heartbeat) |
|---|---|---|
| 触发 | Cron 表达式，精确定时 | 固定间隔（15m/30m/1h/2h） |
| 输出 | 每次都产出结果 | **大多数时候静默**，有事才通知 |
| 会话 | 每次创建独立会话 | 一个持久会话，Agent 有上下文记忆 |
| 适用 | "每周一早上生成报告" | "有紧急邮件就告诉我" |

**核心区别**：心跳巡查大多数时候什么都不做（Agent 回复 `HEARTBEAT_OK`，消息被静默丢弃），只有发现需要关注的事项才通知你。

## 快速开始

### 1. 打开设置 → 心跳巡查

在 Settings 面板左侧找到 **Heartbeat** 标签页。

### 2. 设置工作目录（可选）

心跳巡查有自己独立的工作目录，和 Cowork 主工作区互不干扰。如果不设置，会使用 Cowork 的工作目录。

### 3. 配置巡查提示词

这是最关键的一步。在「巡查提示词」里写你希望 Agent 检查什么。用自然语言即可，例如：

```
检查我的邮箱有没有紧急邮件（主题包含"紧急"或"ASAP"）。
如果过去 30 分钟内有新的 GitHub Issue，告诉我。
如果没有需要关注的事项，回复 HEARTBEAT_OK。
```

### 4. 创建 HEARTBEAT.md（可选进阶）

如果你的巡查清单比较复杂，可以点击设置面板里的「创建 HEARTBEAT.md 模板」按钮。Agent 每次巡查时会读取这个文件。

### 5. 启用并设置间隔

打开开关，选择巡查间隔。建议从 30 分钟开始。

## HEARTBEAT.md 怎么写

HEARTBEAT.md 是一个纯 Markdown 文件，放在心跳工作目录下。用自然语言写清单即可：

```markdown
# 心跳巡查任务

## 邮件监控
- 检查收件箱有没有紧急邮件（主题包含"紧急"、"ASAP"、"P0"）
- 如果有，摘要内容并通知我

## 开发监控
- 检查 GitHub 仓库 myorg/myrepo 过去 30 分钟是否有新 Issue
- 检查 CI/CD 最近一次构建是否失败

## 日历提醒
- 如果未来 2 小时内有会议，提醒我

## 服务器健康
- 检查 server.example.com 的 CPU 使用率，超过 80% 告警
```

**原则**：
- 每条任务用一行自然语言描述
- 写清楚判断条件（什么时候该通知、什么时候不用管）
- 保持清单简短（3-8 条），控制 token 消耗
- 最后一条通常写"如果没有需要关注的事项，回复 HEARTBEAT_OK"

## 常见使用场景

### 邮件秘书
```
检查我的邮箱收件箱。
如果有包含"紧急"、"urgent"、"ASAP"的邮件，摘要给我。
如果有超过 2 小时未读的邮件超过 5 封，提醒我清理。
否则回复 HEARTBEAT_OK。
```

### GitHub 值班
```
检查 GitHub 仓库 myorg/myapp：
- 过去 30 分钟是否有新 Issue 或 PR
- 是否有 CI 构建失败
- 是否有指派给我的 review 请求
如果都没有，回复 HEARTBEAT_OK。
```

### 服务监控
```
检查以下服务状态：
- ping api.example.com 是否正常
- 检查 Docker 容器 web-app 是否在运行
- 检查磁盘使用率是否超过 90%
如果一切正常，回复 HEARTBEAT_OK。
```

### 新闻情报
```
搜索过去 30 分钟关于"AI安全"的重要新闻。
如果有重大新闻，简要摘要；否则回复 HEARTBEAT_OK。
```

### 空闲签到
```
如果我超过 4 小时没有任何 Cowork 会话，发一条友好的签到消息。
否则回复 HEARTBEAT_OK。
```

## 行为细节

### 静默机制
- Agent 回复包含 `HEARTBEAT_OK` → 消息被丢弃，不推送通知
- Agent 回复有实质内容 → 推送到配置的 IM 渠道

### 重复抑制
- 如果 Agent 在 24 小时内返回完全相同的告警内容，第二次会被静默抑制
- 防止同一个问题反复通知你

### 上下文记忆
- 所有心跳巡查共用一个 Cowork 会话
- Agent 通过 Claude SDK 的 session resume 机制保持上下文
- Agent 知道上一次检查了什么、发现了什么
- 你可以在 Cowork 会话列表中找到 `[Heartbeat] 巡查` 查看完整对话记录

### 活跃时段
- 设置起止时间后，超出时段的心跳 tick 会被自动跳过
- 避免凌晨 3 点给你推送"一切正常"

## 通过对话配置心跳

你可以在 Cowork 对话中直接告诉 Agent 你想让心跳做什么。如果安装了 `heartbeat-manager` 技能，Agent 可以自动帮你：

- 启用/禁用心跳
- 修改巡查间隔
- 编辑 HEARTBEAT.md 内容
- 更新巡查提示词

例如：
> "帮我设置心跳巡查，每 30 分钟检查一次邮箱有没有紧急邮件，有的话通过 Telegram 通知我。"

Agent 会自动完成配置。

## 成本控制

每次心跳 tick 都会消耗 API token。建议：

- 巡查清单保持简短（3-8 条）
- 间隔不要太短（30 分钟通常足够）
- 设置活跃时段（如 08:00-22:00），非工作时间不巡查
- 如果某项检查可以用简单的命令行完成（如 `ping`、`curl`），写明让 Agent 用工具而非 LLM 推理

## 常见问题

**Q: 心跳和定时任务能同时用吗？**
A: 可以。心跳适合"有事才通知"的监控场景，定时任务适合"到点必须执行"的固定工作。

**Q: 心跳会创建很多会话吗？**
A: 不会。心跳复用同一个 Cowork 会话，所有巡查对话在一个地方。

**Q: 我能看到心跳的对话记录吗？**
A: 能。在 Cowork 会话列表中找到 `[Heartbeat] 巡查`，点进去就是完整的对话。

**Q: 我删了心跳会话怎么办？**
A: 下次心跳 tick 时会自动创建一个新的。

**Q: 不写 HEARTBEAT.md 可以吗？**
A: 可以。设置面板里的「巡查提示词」已经够用了，HEARTBEAT.md 是进阶选项。
